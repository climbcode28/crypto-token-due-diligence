# Project credibility and delivered work

Start from the exact mint's captured links and the complete original request. Record
who published each dated claim, what was actually delivered, what remains promised,
and the strongest contrary evidence. A public repository, audit badge or indexer
link is a source lead, not a runtime/control attestation.

Use immutable revision/tree records for meaningful code review. Distinguish owner,
fork, archived status, language, commit activity and released functionality. Capture
an audit's actual product/revision/deployment, dates, findings and exclusions. Keep
source publication, third-party verification, executable byte correspondence and an
independently reproduced build separate. Failed repository/explorer access does not
negate affirmative primary evidence elsewhere.

Explain holder rights, discretionary mechanisms, treasury/controller paths, external
dependencies and observable operating record in plain language. Ordinary fees and
buybacks are not automatically abusive; popularity cannot excuse an observed dangerous
control. Quote actual user requirements and address every supplied source/ask with
an evidence-supported answer or a precise gap. Never invent a human identity from a
wallet or make an adverse allegation from missing research.
